# Telegram 管理员机器人

本说明按 PR #8 的免费源码实际处理器编写；不是生产配置或在线通知验收。需要在面板开启 Telegram，配置自己的 bot token 和管理员聊天 ID；管理员权限按发送者 Telegram ID 校验。群聊接收 ID 不等于管理员用户 ID。本文不公开任何凭据。[阶段5清理审计](stage5-advertising-docs.md)和[截图来源](screenshots/README.md)分别说明源码与浏览器证据。

## 保留的操作

- `/start`、`/help`：显示菜单；`/status` 是机器人响应状态，不是完整服务器监控；`/id` 返回自己的 Telegram ID。
- 管理员菜单按四组组织：状态查询（服务器用量、入站用量、在线客户端、排序流量报告、额度/到期查询、封禁日志）；客户端管理（查询、添加客户端、已有额度/到期/IP 限制与启停设置、手动清零）；备份（数据库备份）；系统操作（重启面板、订阅转换、命令帮助）。各组可返回主菜单，未增加新产品能力。普通用户仍保留自己的客户端用量和命令帮助。
- `/usage <email>`：管理员查客户端；非管理员只能查询与自己 Telegram ID 绑定的客户端。`/inbound <remark>` 为管理员查询入站。
- `/restart`：预览重启 Xray 的连接中断影响，确认或取消后结束；`/restartx` 或菜单重启面板同样须确认。**这些操作会改变运行状态并可能短暂断网**；原回复不等于独立健康检查。
- `/subconverter`：检测订阅转换服务；不存在时可确认安装，保留原安装及结果通知。**安装会改变服务器**，本次源码清理没有执行安装或修改安装器。

已移除抽奖入口/回调/开奖/邀请、每日诗词、随机美图、新闻抓取、VPS 推荐/affiliate，以及 Telegram 一键配置的 Pro 购买占位命令和按钮；不解锁任何 Pro 功能。旧抽奖数据库表和历史数据继续兼容，不执行删除表或数据迁移。

清零单个/全部客户端流量、清除客户端 IP 记录、删除 Telegram 用户绑定均明确显示操作目标，并提供确认/取消；删除绑定不会删除客户端。所有按钮验证当前管理员、匹配的私人聊天、消息及 20 分钟有效期，重复确认不得重复变更，取消后的旧确认按钮失效。客户端添加草稿按管理员独立保存，两人可交错操作；失败提交可修正重试，取消、关闭键盘和超时隔离各自会话。数据库导入在首次切换数据库前撤销旧绑定请求、草稿及按钮；外部 Telegram issuance 文件仍须保留，不能随旧业务备份回滚。

## 管理员添加入站

客户端管理 → 添加入站，仅管理员私聊可用。本次冻结支持 VLESS + WebSocket + TLS 和 VMess + WebSocket + TLS，不含 Reality、Trojan、Shadowsocks。Xray 当前仍支持这两种模板，但会给出 WS / VMess 弃用警告；本向导不扩展模板范围。

选择模板后，逐步回复当前提示消息：备注、监听端口、TLS 域名、已有 TLS 证书所在入站 ID、首客户端标识、整数 GB 额度（0 不限）、到期日期 YYYY-MM-DD（UTC 零时，0 不限）、月重置日（1–31，0 关闭）。必须使用 Telegram 的“回复”指向当前提示；旧消息、其他管理员、普通用户、超时按钮均不可推进。每名管理员独立草稿；同一管理员重新开始会替换自己的草稿，取消/关闭键盘/数据库恢复撤销旧草稿。预览的“修正 / 重新填写”从备注重新开始，保留所选模板。

证书只复用已有入站的单个 certificateFile/keyFile 引用，检查本地证书密钥配对，并在提交前解析 leaf 证书、校验域名及 NotBefore/NotAfter；支持域名匹配的自签名和通配符证书，不要求公有 CA。不接受聊天中的私钥或内联证书，不签发证书，不开放防火墙、不远程安装。WS path 使用现有编辑器默认 `/`，VLESS decryption 使用其默认 `none`，其他未指定协议参数由当前核心默认处理。入站归属面板首个用户（机器人管理员未建立面板账户映射），tag 与现有 API 的空监听地址规则一致为 inbound-端口；首客户端使用生成的 UUID/subId，流量身份和月重置登记复用实际 AddInbound 服务。

创建前仅预览非秘密字段，不发送 UUID、密码、私钥或连接链接。端口冲突、协议/参数和实际核心配置 Build 均在提交前校验；只有明确确认才提交。数据库写入/提交失败不调用核心且保留草稿，可修正后用新按钮重试；已提交后核心应用失败明确提示“核心应用失败 / 待重试”，保留入站和客户端数据并使用现有待重启标记，不删除已提交数据，也不自动执行重启。普通成功和待重试结果均不播报秘密。管理员需要连接链接或 QR 时，可主动点击提交结果上的按钮获取；按钮绑定私人管理员、消息和 20 分钟有效期，数据库恢复撤销旧按钮。请求重新读取已提交入站和客户端身份，目标删除或权限失效时拒绝；复用订阅链接序列化，QR 使用相同链接及现有面板的 400px / L 纠错规则，不自动推送连接秘密。已更改为其他传输模板或配置 externalProxy 的目标须使用完整面板获取。

## 一般会通知什么

| 通知 | 条件与边界 |
| --- | --- |
| 管理员运营摘要 | 开启 bot 后按 `tgRunTime` 的 cron 执行；为空回退 `@daily`，按面板时区。现有任务要求 Xray 正在运行。每名管理员一条，包含实际服务器运行时长、CPU、内存、磁盘、TCP/UDP、主机累计网络流量、面板/Xray 版本及核心状态；不抓诗图新闻，也不为报告查询公网 IP。主机网络流量不是客户端周期用量。 |
| CPU 超阈值告警 | `tgCpu > 0` 才注册检查；10 秒采样，连续三次超阈值才通知，两次至少间隔 10 分钟。保留原行为。 |
| 登录成功/失败 | bot 运行且 `tgBotLoginNotify` 开启；保留用户名、IP、时间及登录结果，阶段 1 已移除密码参数、通知和失败登录日志转发，不记录或发送尝试的密码。建议仅发送到受控私人管理员聊天，不要公开载荷。 |
| 设备超限提醒 | 入站启用且设置设备限制，核心运行、可读取访问日志并识别客户端；持续超限约三分钟触发原设备限制处理时发送管理员通知。通知不是独立证明核心封禁成功；没有新增解封通知。 |
| 数据库备份 | 管理员菜单或已认证的 `/panel/api/backuptotgbot` 请求触发；没有自动定时备份任务。数据库含敏感配置，只交给受控管理员。 |
| 订阅转换结果 | 用户确认安装后，原安装流程发送完成/失败等结果及已有相关警告；不代表无人操作就会安装。 |
| 重启操作回复 | 管理员手动发起/确认时返回原确认、取消或结果提示；没有新增启动/掉线监控。 |

额度将尽/即将到期及禁用情况仍可从管理员菜单查询。源码保留客户端 Telegram ID 的额度/到期提醒辅助函数，但当前没有发现调用或定时注册，**不宣称会自动发送**。独立月重置没有 Telegram 专用开关或自动完成通知，本次不新增。

### 开关、时区与频率

在面板设置的 Telegram 页配置，保存后按现有面板重启流程让任务注册生效；不要把保存成功当作机器人在线验收。

- `tgBotEnable` 默认关闭；`tgBotToken` / `tgBotChatId` 默认空。可配置 `tgBotProxy` / `tgBotAPIServer`，均为用户自己的通信目标，不使用内置第三方 token 或收件人。
- 摘要使用 `tgRunTime`（默认 `@daily`）：例如 `0 0 8 * * *` 每日 08:00、`0 0 8 * * 1` 每周一 08:00、`0 0 8 1 * *` 每月1日 08:00。使用六字段 cron，含秒（秒、分、时、日、月、星期），与实际 scheduler 的 `WithSeconds()` 一致；按 `timeLocation`（默认 `Local`，即运行主机时区）调度。读取失败或空值回退每日；非空但语法错误会注册失败，不能承诺自动回退。没有独立摘要开关或逐项内容开关；关闭 bot 会同时关闭其他 bot 通知。
- `tgBotLoginNotify` 默认开启，但仍要求 bot 正在运行；`tgCpu` 默认 80，设为 0 不注册 CPU 检查。CPU 检查间隔/连续次数/10分钟冷却是源码固定策略，不是可配置频率。
- `tgBotBackup` 默认关闭且界面有开关，但当前全源码只有 getter 定义、没有调用或定时备份注册；开启它不能据此宣称有自动备份。手动备份仍可用。
- `externalTrafficInformEnable` / `externalTrafficInformURI` 是独立的、默认关闭/空的外部流量上报配置；开启时现有采集任务按10秒节奏向用户配置 URI 发送客户端/入站流量，不是 Telegram 摘要。目标应由管理员控制；本轮保留该显式配置功能。

模板到期日期使用 UTC，而月重置和运营摘要使用面板时区；两者不能混用。自签名证书通过向导的域名/时间校验，不等于客户端自动信任它；客户端信任配置及 DNS/公网可达性仍需管理员另行确认。

## 验证与部署边界

回归测试通过本地 Telegram API 接收真实菜单与报告载荷，验证已退役回调无动作、正常管理员菜单保留、摘要为单条且无额外 HTTP 获取。测试使用临时数据库和合成 bot 标识，不调用生产 bot、重启或安装。源码合并不等于已部署：已安装面板须另获授权重建/替换程序才会生效。

本轮没有登录真实 Telegram 客户端或配置生产 bot，因而没有机器人聊天截图；本地 handler/API 载荷验收不是 Telegram 客户端画面。网页截图仅展示真实认证的隔离工具导航页，不证明 bot 已部署。恢复撤销与双管理员操作采用前阶段已通过的真实本地 handler/SQLite 证据；不新增断电、跨进程发行账本或生产安装验收声明。
